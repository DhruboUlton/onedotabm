# WebApp Demo Showcase — how to add a demo

Every demo is a self-contained mini-site under `src/app/webapp-demo/<category>/<demo>/`.
Demos never import from each other, so one demo can never break another.

## The category folders

These already exist and are ready to use. Drop your demos straight into them:

```
src/app/webapp-demo/
├── ecommerce/      ← demo-01 lives here
├── crm/
├── blog/
├── organization/
├── portfolio/
├── education/
├── restaurant/
├── booking/
├── saas/
└── other/
```

A category folder holds nothing but demo folders. The category listing page at
`/webapp-demo/<category>` is generated by `src/app/webapp-demo/[category]/page.tsx`,
so you never add a `page.tsx` at the category level.

## Adding a demo — 4 steps

### 1. Create the folder

```
src/app/webapp-demo/crm/demo-01/
├── layout.tsx              ← demo root: metadata, providers, <DemoFrame />
├── (storefront)/           ← the public-facing site (route group, no URL segment)
│   ├── layout.tsx          ← header, footer, page chrome
│   └── page.tsx            ← /webapp-demo/crm/demo-01
├── admin/                  ← optional admin panel
│   ├── layout.tsx
│   └── page.tsx            ← /webapp-demo/crm/demo-01/admin
├── _components/            ← private: not routed
├── _context/               ← private: state providers
└── _data/                  ← private: mock data
```

Folders starting with `_` are private in the App Router — Next.js never turns them
into URLs, so demo internals stay out of routing.

### 2. Add `<DemoFrame />` to the demo's root `layout.tsx`

One line, no props, once per demo. It covers the storefront and the admin panel:

```tsx
import { DemoFrame } from '@/demos/components/DemoFrame';

export default function Demo01Layout({ children }: { children: React.ReactNode }) {
  return (
    <StoreProvider>
      {children}
      <DemoFrame />
    </StoreProvider>
  );
}
```

`DemoFrame` reads the URL to work out which category, which demo and whether the
visitor is on the storefront or in the admin panel, then pulls the business name
and whether an admin panel exists from the registry. It also renders its own
bottom spacer, so your layouts do not need to leave room for the bar.

Two optional overrides, both rarely needed:

```tsx
<DemoFrame notice="Demo website. Sample data only." name="Acme Logistics" />
```

### 3. Mark the demo as `noindex`

In the same root `layout.tsx`:

```tsx
export const metadata: Metadata = {
  title: { default: 'Business Name — Tagline', template: '%s | Business Name Demo' },
  description: 'Interactive demo built by OneDot ABM.',
  robots: { index: false, follow: false },
};
```

### 4. Register it

Add one entry to `demos` in `src/demos/registry.ts`:

```ts
{
  slug: 'demo-01',
  category: 'crm',
  name: 'Northwind Pipeline',
  description: 'Deal pipeline, contact records and activity timeline with a full sales admin.',
  tags: ['Pipeline', 'Contacts', 'Reports', 'Admin Panel'],
  hasAdmin: true,
  preview: { from: '#0F172A', to: '#38BDF8' },
}
```

That entry is what makes the demo appear on `/webapp-demo` and on its category
page, and it is where `DemoFrame` gets the business name from. A demo that is not
registered still runs, but its bar shows no name and no admin switch.

### 5. Add the card screenshot (optional)

Without a screenshot the card shows a generic wireframe. With one, it shows the
demo's own home page inside a laptop frame.

1. Open the demo at `/webapp-demo/<category>/<demo>` in a browser at a laptop
   width — around 1440px wide.
2. Capture the top of the page. On macOS, `Cmd+Shift+4` then drag, or
   `Cmd+Shift+5` for a window capture.
3. Save it to `public/demo-assets/<category>/<demo>-preview.jpg`. Keep it under
   roughly 300KB; the card renders it about 600px wide, so a 1440px-wide JPEG at
   quality 80 is more than enough.
4. Point the registry entry at it:

```ts
preview: {
  from: '#062E25',
  to: '#E87121',
  image: '/demo-assets/ecommerce/demo-01-preview.jpg',
}
```

The path is absolute from `/public`, so it starts with `/demo-assets`, not
`public/demo-assets`. The card crops the image from the top, so the header and
hero are what show; anything below the fold is cropped away. The gradient stays
as the surround, so `from` and `to` still matter.

Nothing else in the system changes. No shared file needs a new branch, no route
needs editing, and demo 2 is the same four steps with `demo-02`.

## House rules

- **Frontend only.** Mock data in `_data/`, state in React. No database, no API
  routes, no authentication — the admin panel is open on purpose.
- **Fictional details.** Invented business names, `+880 1XXX-XXXXXX` phone
  numbers, `hello@<business>.demo` email addresses, made-up customers.
- **Attribution.** `DemoFrame` carries "Powered by OneDot ABM" automatically.
- **Responsive everywhere**, including the admin panel. Tables become cards below
  `md` rather than scrolling off-screen.
- **No cross-demo imports.** Shared code lives in `src/demos/`; today that is
  `DemoFrame`, the registry and the types, and it should stay that small.
